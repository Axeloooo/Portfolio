## Problem
This follows Andrej Karpathy's makemore lectures from the Neural Networks: Zero to Hero series. The README lists five parts: building makemore, MLP, activations/gradients/BatchNorm, backprop by hand, and WaveNet. The models learn to generate names from the 32,033-name makemore dataset. The repo turns notebook-style lecture code into an installable package with tests and a CLI, so each model can be trained from one command.

## Architecture diagram
```text
Flow
  names.txt --> data.py
  data.py --> bigram.py
  data.py --> models.py
  layers.py --> models.py
  models.py --> train.py
  __main__.py --> data.py
  __main__.py --> bigram.py
  __main__.py --> models.py
  __main__.py --> train.py
  tests/ ..> backprop.py

Details
  names.txt: 32,033 names
  data.py: vocab, 80/10/10 split,, build_dataset
  bigram.py: CountBigram, NeuralBigram
  models.py: build_mlp, build_wavenet
  layers.py: Linear, BatchNorm1d, Tanh,, Embedding, FlattenConsecutive
  backprop.py: forward, manual_backward
  train.py: train, evaluate, sample
  __main__.py: --model bigram, mlp, mlp-bn, wavenet
  tests/: manual grads vs autograd
```

Read left to right: `names.txt` is split and windowed by `data.py`, then feeds the bigram models and the layer-based models built from `layers.py`. Solid arrows mean data flows to; the dotted arrow means the tests import the module. `backprop.py` is a standalone module that only the tests exercise, against `loss.backward()`; no CLI path calls it. `__main__.py` selects a model and calls `train.py`.

## Key decisions
- **Hand-written layers instead of `torch.nn`.** `layers.py` defines `Module`, `Linear`, `BatchNorm1d`, `Tanh`, `Embedding`, `FlattenConsecutive` and `Sequential`, and `train.py` updates parameters with a manual SGD loop (learning rate drops 10x at 75% of steps).
- **One layer for both MLP and tree.** `FlattenConsecutive` flattens the whole context for the MLP and merges neighbouring pairs for the "WaveNet" model in `models.py`. This is the lecture's hierarchical-merge MLP, not a dilated-convolution WaveNet.
- **BatchNorm over 2D and 3D input.** `BatchNorm1d` reduces over `(0, 1)` for `(N, L, C)` input, which the tree model needs, and is covered in `tests/test_models.py`.
- **Manual backward as a separate functional module.** `backprop.py` keeps a forward cache and writes cross-entropy, linear, tanh, collapsed BatchNorm and embedding gradients by hand; `tests/test_backprop.py` compares them to `loss.backward()` with `atol` 1e-5.
- **Dataset shipped inside the package.** Commit `9f3cc27` moved `names.txt` into `src/charlm/` and added package data, with a `--data` flag for other word lists.

## Challenges
- **Install bug.** The dataset first lived at `data/names.txt`, outside the package, so a regular install could not find it. `9f3cc27` fixed this and also made `build_wavenet` reject a block size that is not a power of the group size.
- **Release automation took several passes.** `678735f` switched to a release token, `b136fa7` went back to the built-in `GITHUB_TOKEN`, and `e0897c7` and `886d9d4` sync `main` back into `devel`.
- **Gradient check is narrow.** The test covers only the two-layer BatchNorm MLP in `backprop.py`; the `Module`-based models rely on autograd.
- **Short default runs.** The README notes the CLI defaults finish on a CPU in seconds, while the lectures train for 100k-200k steps.

## Results
- Four models run from `python -m charlm --model bigram|mlp|mlp-bn|wavenet`, reporting train, dev and test loss.
- 21 test functions in five files under `tests/` cover bigram, data, models, CLI and the gradient check.
- CI (`.github/workflows/ci.yml`) runs ruff, black, mypy, prettier and pytest on Python 3.10 and 3.13. Three releases (v1.0.0, v1.1.0, v1.1.1) are in `CHANGELOG.md`.
- The only runtime dependency is `torch>=2.2`. No loss values or sample names appear in the repo.
