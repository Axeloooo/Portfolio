## Problem
A single place to show work experience, education, research, projects and skills, plus a blog. Content, sections, CI and a release workflow are all maintained in the one repo.

## Architecture diagram
```text
Groups
  Content: src/data/resume.tsx, content/*.mdx
  src/app (Next.js 14 App Router): layout.tsx, page.tsx, blog/page.tsx, blog/[slug]/page.tsx

Flow
  src/data/resume.tsx --> page.tsx
  page.tsx --> src/components
  content/*.mdx --> src/data/blog.ts
  src/data/blog.ts --> blog/page.tsx
  src/data/blog.ts --> blog/[slug]/page.tsx
  layout.tsx --> page.tsx
  layout.tsx --> blog/page.tsx
  layout.tsx --> Vercel Analytics
  src/data/resume.tsx --> layout.tsx
  GitHub Actions ..> src/app (Next.js 14 App Router)

Details
  src/data/resume.tsx: DATA object
  page.tsx: home sections
  src/data/blog.ts: gray-matter + unified
  src/components: ProjectCard, ResumeCard, magicui
  Vercel Analytics: + Speed Insights
  GitHub Actions: ci.yml, release.yml
```

There is no backend or database. All home-page content comes from one `DATA` object in `src/data/resume.tsx`; blog posts are `.mdx` files turned into HTML by `src/data/blog.ts`. `layout.tsx` wraps both routes and loads the Vercel packages, and the two workflows in `.github/workflows/` run on pull requests and on pushes to `main`.

## Key decisions
- **Content in one typed data file.** `src/data/resume.tsx` holds work, education, skills, projects and links, so adding a project is one object edit. Axel added `research` and `leadership` sections (`3fa4274`), rendered in `src/app/page.tsx`.
- **Blog as MDX files, no CMS.** `src/data/blog.ts` reads `content/` with `fs`, parses frontmatter with `gray-matter`, and highlights code with `rehype-pretty-code`. Only one placeholder post, `content/hello-world.mdx`, exists.
- **Theme-aware favicons.** `next-themes` handles the class-based dark mode, and `src/components/favicon-switcher.tsx` with `public/favicon-{light,dark}.ico` (`44dc181`) swaps the icon.
- **Squash-merge and Conventional Commit titles.** The README (Contributing) requires feature branches into `devel` into `main`, always squash-merged, with PR titles in Conventional Commit form so semantic-release (`.releaserc`, `release.yml`) can read the history.
- **CI gate.** `ci.yml` runs `npm run lint` and `npm run build` on pull requests to `main` and `devel`.

## Challenges
- **Type error in an animation component.** `0d4c7d0` ("Fixed type issue by casting to any") added `margin: inViewMargin as any` in `src/components/magicui/blur-fade.tsx`, the cast is still present.
- **Lint toolchain churn.** On 2026-01-19, `bd56d1b` raised `eslint-config-next` to ^16 and `a1ed52a` raised ESLint to ^9, then `df643d6` set them back to `eslint` ^8.57 and `eslint-config-next` ^14.2. No message gives a reason.
- **Node runtime pin.** `9c60ae0` pinned `engines.node` to `24.x` because, per its message, Vercel is deprecating Node.js 20 and the field overrides the dashboard setting. `ci.yml` still uses `lts/*` and the README says "Node.js LTS", so CI could drift from the deploy runtime.
- **Unfinished links.** `src/app/blog/[slug]/page.tsx` points the default OpenGraph image at `/og?title=...`, but `src/app/og` does not exist. Many entries in `resume.tsx` use `href: "#"`, and the package name is spelled `porfolio`.
