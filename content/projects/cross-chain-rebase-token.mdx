## Problem
The project explores a token whose balance grows over time and whose holders keep the interest rate they had when they deposited, even after moving the token to another chain. A `Vault` takes ETH and mints `RebaseToken`; a CCIP token pool carries each user's rate along with the bridged amount. ## Architecture diagram
Read left to right: ETH enters the `Vault` on Sepolia, which mints the token. Bridging goes through the CCIP router and the pools, which burn on the source chain and mint on Arbitrum Sepolia with the original user's rate. The vault exists only on the source chain.

## Key decisions
- **Interest is realized lazily.** `balanceOf` in `src/RebaseToken.sol` computes principal plus accrual from the user's rate and elapsed seconds; the accrued amount is minted only when the user mints, burns or transfers.
- **The global rate can only decrease.** `setInterestRate` is owner-only and reverts if the new rate is not lower; `testInterestRateCanOnlyDecrease` covers it, so earlier depositors keep better rates.
- **The rate travels with the tokens.** `src/RebaseTokenPool.sol` encodes the sender's rate into CCIP `destPoolData` in `lockOrBurn` and decodes it in `releaseOrMint`.
- **Roles are split.** `AccessControl` grants `MINT_AND_BURN_ROLE` to the vault and pools, while `Ownable` guards rate changes (commit df1d23c). `IRebaseToken` keeps vault and pool decoupled from the token (e8f86b2).
- **CI first, release automation later.** The CI workflow `test.yml` runs `forge fmt --check`, `forge build --sizes` and `forge test` from the first setup commit (fde4081). `semantic-release` (`release.yml`, `.releaserc`) was added in d47ad66 on the last day; most commits use `feat:`/`fix:` prefixes, but the early ones do not.
- **Rate inheritance on transfer.** In `src/RebaseToken.sol`, a recipient with a zero balance takes over the sender's rate; a recipient who already holds tokens keeps their own.

## Challenges
- **Cross-fork testing.** `test/CrossChain.t.sol` forks Sepolia and Arbitrum Sepolia and uses `CCIPLocalSimulatorFork`, which must be called while the source fork is active, so the test switches forks repeatedly and warps time on the remote fork before comparing balances.
- **CI needs live RPC endpoints.** Commits 30cb658 and 72292ff reworked how RPC URLs reach the tests; CI reads them from repository secrets.
- **Compiler settings.** `via_ir = true` was enabled in b2f7530 and the pragma was fixed in a4ab2a0. **TODO (Axel):** What problem did `via_ir` solve?
- **Accrued interest is not backed.** Redeeming interest only works if extra ETH is sent to the vault (`addRewardsToVault` in `test/RebaseToken.t.sol`), so the vault can hold less ETH than the tokens it has issued.

## Results
The repo contains the three contracts, deploy/configure/bridge scripts (`Deployer.s.sol`, `ConfigurePool.s.sol`, `BridgeTokens.s.sol`), nine unit test functions (some fuzzed) and one cross-chain test, `testBridgeAllToken`. That test bridges Sepolia to Arbitrum Sepolia and back and asserts the user's rate is equal on both sides (`CrossChain.t.sol`). It runs on forks with the local CCIP simulator only.
